# PDFsmith — Windows-установщик, ассоциация .pdf и «приложение по умолчанию»

Дата: 2026-06-09
Статус: утверждено

## Цель

Сделать так, чтобы PDFsmith устанавливался как обычное Windows-приложение:
один `setup.exe`, регистрация в системе, появление в меню «Открыть с
помощью» и в *Параметры → Приложения по умолчанию*, возможность стать
обработчиком `.pdf` по умолчанию в один клик.

## Контекст

- Приложение на Rust (`eframe`/`egui`), бинарь `pdfsmith-app.exe`.
- Уже принимает путь к файлу первым аргументом командной строки
  (`crates/pdfsmith-app/src/main.rs:27`), поэтому открытие через «Открыть
  с помощью» на уровне приложения уже работает.
- Приложению нужна `pdfium.dll` рядом с `.exe` — DLL грузится из папки
  бинаря (`main.rs:89`).
- Иконки в проекте нет — генерируется в рамках этой работы.

## Решения

| Вопрос | Решение |
|---|---|
| Технология установщика | Inno Setup (один `setup.exe`) |
| Тип установки | Per-user, без прав администратора |
| «По умолчанию» | Регистрация как кандидата + системный диалог выбора в конце |
| Иконка | Генерируется в рамках работы (плейсхолдер) |

## 1. Что ставим и куда

- **Inno Setup**, режим per-user: `PrivilegesRequired=lowest`, без UAC.
- **Папка установки:** `%LocalAppData%\PDFsmith\`.
- **Состав:**
  - `pdfsmith.exe` — бинарь переименовывается с `pdfsmith-app` на
    `pdfsmith` через `[[bin]]` name в `crates/pdfsmith-app/Cargo.toml`.
  - `pdfium.dll`.
  - `pdfsmith.ico`.
- **Ярлыки:** в меню «Пуск» всегда; на рабочем столе — по галочке
  (Tasks, по умолчанию выключено).

## 2. Иконка

В проекте появляется `pdfsmith.ico` (мульти-размерный: 16/32/48/256).

- Вшивается в `pdfsmith.exe` через `winresource` в `build.rs` крейта
  `pdfsmith-app` — для окна и панели задач.
- Тот же `.ico` используется как значок `.pdf`-файлов в проводнике
  (через ProgID `DefaultIcon`).

Иконка генерируется как простой плейсхолдер в рамках реализации.

## 3. Ассоциация с `.pdf`

Регистрация по модели Windows «Default Programs» целиком в **HKCU**
(админ не требуется). Все ключи пишет/удаляет установщик.

```
HKCU\Software\Classes\PDFsmith.Document
    (default)            = "PDF-документ"
    DefaultIcon          = "<dir>\pdfsmith.ico"
    shell\open\command   = "\"<dir>\pdfsmith.exe\" \"%1\""

HKCU\Software\PDFsmith\Capabilities
    ApplicationName      = "PDFsmith"
    ApplicationDescription = "Просмотрщик PDF"
    FileAssociations\.pdf = "PDFsmith.Document"

HKCU\Software\RegisteredApplications
    PDFsmith             = "Software\PDFsmith\Capabilities"

HKCU\Software\Classes\.pdf\OpenWithProgids
    PDFsmith.Document    = ""   (REG_NONE)
```

Результат: PDFsmith появляется в меню **«Открыть с помощью»** и в списке
*Параметры → Приложения по умолчанию*.

## 4. Выбор «по умолчанию»

Программно назначить обработчиком по умолчанию Windows 10/11 не
позволяет — это делает только пользователь через системный UI. Поэтому:

- В установщике галочка **«Сделать PDFsmith приложением по умолчанию
  для PDF»** (Tasks, по умолчанию включена).
- Если отмечена — в конце установки открывается **системный диалог
  выбора** для `.pdf` (`SHOpenWithDialog` с флагом для назначения
  ассоциации). Пользователь подтверждает в один клик.
- Фолбэк, если диалог недоступен: открыть страницу *Параметры →
  Приложения по умолчанию*.

## 5. Удаление

Деинсталлятор Inno Setup удаляет:

- файлы и папку `%LocalAppData%\PDFsmith\`;
- ярлыки (Пуск, рабочий стол);
- все ключи реестра из раздела 3 (ProgID, Capabilities,
  RegisteredApplications, запись в `.pdf\OpenWithProgids`).

## Вне рамок (YAGNI)

- Per-machine / корпоративное развёртывание (MSI, GPO).
- Подпись кода сертификатом.
- Авто-обновления.
- Регистрация других форматов, кроме `.pdf`.

## Критерии готовности

1. `setup.exe` ставит приложение без прав администратора.
2. После установки PDFsmith есть в «Открыть с помощью» для `.pdf`.
3. PDFsmith виден в *Параметры → Приложения по умолчанию*.
4. Двойной клик по `.pdf` (после выбора по умолчанию) открывает файл в
   PDFsmith, и файл реально отображается.
5. Деинсталляция не оставляет файлов и ключей реестра.
