# PDFsmith — установщик, обновления через GitHub и CI-релизы

Дата: 2026-09-23
Статус: на ревью

## Цель

Офисные ПК получают PDFsmith запуском одного `pdfsmith-setup.exe`, а новые
версии — из GitHub Releases репозитория `denfry/pdfsmith`. По умолчанию
приложение **предлагает** обновиться; в настройках есть переключатель
«Автоматически устанавливать обновления».

Кроме того, приложение само предлагает стать программой по умолчанию для
PDF (раздел 6).

Это подпроект №1 из серии. Следующие (каждый — свой спек): №2 вкладки —
несколько открытых PDF в одном окне и один экземпляр приложения (двойной клик
по PDF открывает вкладку в уже запущенном окне); №3 конвертация Word/Excel →
PDF через MS Office + сжатие + пароль; №4 OCR; №5 редактирование текста,
водяные знаки, колонтитулы, скрытие данных; №6 PDF → Word/Excel.

## Контекст и ограничения

- Windows 10/11 x64. На всех ПК прямой доступ к github.com, MS Office есть.
- Меньше ~50 машин, централизованного развёртывания нет; ставит каждый сам.
- Репозиторий публичный — релизы скачиваются без токенов.
- Установщик уже сделан в ветке `origin/feat/windows-installer` (коммит
  `84ab213`): `installer/pdfsmith.iss`, `crates/pdfsmith-app/build.rs`,
  `crates/pdfsmith-app/assets/pdfsmith.ico`, `assets/make_icon.py`,
  `installer/README.md`. Ветка разошлась с `main`; эти файлы от кода
  приложения не зависят и переносятся в `main` как есть, затем дорабатываются.
  Предыдущий спек: `2026-06-09-windows-installer-design.md` — остаётся в силе
  в части ассоциации `.pdf`, «по умолчанию» и удаления.
- Установленная сборка 0.1.0 с `AppId {8F3B6A2C-1D4E-4C7A-9B12-A1B2C3D4E5F6}`
  уже есть на машине разработчика; `AppId` не меняем, чтобы новые версии
  ставились поверх.
- `pdfium.dll` версии 151.0.7881.0 (chromium/7881). В CI берётся из
  `bblanchon/pdfium-binaries`, тег `chromium/7881`, архив `pdfium-win-x64.tgz`.
- Дисковый кэш приложения лежит в `%LOCALAPPDATA%\pdfsmith\cache` — это та же
  папка, что и установка (пути в Windows регистронезависимы).

## 1. Установщик (доработка `installer/pdfsmith.iss`)

Остаётся: per-user в `%LocalAppData%\PDFsmith`, `PrivilegesRequired=lowest`,
ассоциация `.pdf` в HKCU, галочка «по умолчанию», ярлык в «Пуск».

Добавляется:

- **Версия снаружи.** `#ifndef AppVersion` → `#define AppVersion "0.0.0"`;
  CI передаёт `ISCC /DAppVersion=1.2.3`. `VersionInfoVersion` тоже из неё
  (поэтому только `X.Y.Z`, без суффиксов — CI проверяет формат тега).
- **Закрытие работающей программы:** `CloseApplications=force`,
  `RestartApplications=no`.
- **Диалог «по умолчанию» только в интерактивном режиме.** Inno запоминает
  выбранные задачи прошлой установки, поэтому без проверки тихое обновление
  открыло бы диалог. Условие: `WizardIsTaskSelected('setdefault') and not
  WizardSilent`.
- **Перезапуск после обновления.** Секция `[Run]`:
  `Filename: "{app}\pdfsmith.exe"; Flags: nowait skipifnotsilent;
  Check: ShouldRelaunch`, где `ShouldRelaunch` — наличие параметра
  командной строки `/RELAUNCH`. Обычная интерактивная установка сохраняет
  стандартный флажок «Запустить PDFsmith» (`postinstall skipifsilent`).
- **Чистка при удалении:** `[UninstallDelete]` для `{app}\cache` и
  `{app}\updates` (тип `filesandordirs`). Настройки в
  `%APPDATA%\PDFsmith` не удаляются.

Командная строка обновления:
`pdfsmith-setup.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART [/RELAUNCH]`.

## 2. Релизы и CI (`.github/workflows/`)

**`release.yml`** — на push тега `v*`, раннер `windows-latest`:

1. Проверить, что тег без `v` равен `workspace.package.version` в корневом
   `Cargo.toml`; иначе упасть с понятной ошибкой.
2. Скачать `pdfium-win-x64.tgz` (chromium/7881), положить `bin/pdfium.dll`
   в корень репозитория.
3. `cargo test --workspace` (тесты с PDFium, требующие `test_pdfs/`,
   пропускаются — эти файлы не публикуются).
4. `cargo build --release --bin pdfsmith`.
5. Inno Setup: использовать установленный на раннере, если есть; иначе
   `choco install innosetup`. `ISCC /DAppVersion=<версия> installer\pdfsmith.iss`.
6. Посчитать SHA-256 → `pdfsmith-setup.exe.sha256` (формат `<hex>  pdfsmith-setup.exe`).
7. Сгенерировать `latest.json`:
   ```json
   {
     "version": "1.2.3",
     "notes": "<текст аннотированного тега или пусто>",
     "url": "https://github.com/denfry/pdfsmith/releases/download/v1.2.3/pdfsmith-setup.exe",
     "sha256": "<hex>"
   }
   ```
8. Создать Release `v1.2.3` (`gh release create`) и загрузить три файла.

**`ci.yml`** — на push в `main` и pull request: `cargo test --workspace` и
`cargo build --release`.

Процесс выпуска для разработчика: поднять `version` в `Cargo.toml`, коммит,
`git tag -a v1.2.3 -m "что нового"`, `git push --follow-tags`.
Описывается в `installer/README.md`.

## 3. Крейт `pdfsmith-update`

Новый крейт в workspace, без зависимости от egui. Ответственность: узнать,
есть ли новая версия, скачать и проверить установщик, запустить его.

Зависимости: `ureq` (rustls, синхронный), `serde` + `serde_json`,
`semver`, `sha2`.

Модули:

- **`manifest`** — `struct Manifest { version, notes, url, sha256 }`,
  разбор `latest.json`; `validate()` проверяет, что `url` начинается с
  `https://github.com/denfry/pdfsmith/releases/download/`, `sha256` —
  64 hex-символа, `version` — валидный semver.
- **`decide`** — чистые функции:
  - `is_newer(current, candidate) -> bool` (semver; пре-релизы не
    предлагаются, если текущая версия не пре-релиз);
  - `should_check(last_check, now) -> bool` — не чаще раза в 12 часов;
  - учёт `skipped_version`: пропущенная версия не предлагается повторно,
    более новая — предлагается.
- **`download`** — скачивание в
  `%LOCALAPPDATA%\PDFsmith\updates\pdfsmith-setup-<ver>.exe.part` с
  колбэком прогресса и флагом отмены; SHA-256 на лету; при совпадении —
  rename в `.exe`, при несовпадении — удаление и ошибка. Уже скачанный
  и проверенный файл той же версии повторно не качается. `cleanup()`
  при старте удаляет из папки установщики версий не новее текущей.
- **`apply`** — запуск установщика отсоединённым процессом
  (`DETACHED_PROCESS`) с аргументами из раздела 1; вызывающий код
  сразу после этого завершает приложение.

Источник манифеста:
`https://github.com/denfry/pdfsmith/releases/latest/download/latest.json`
(прямая ссылка на файл релиза, не REST API — лимит 60 запросов/час на IP
не касается офиса за одним NAT). Таймауты: соединение 10 с, чтение 30 с.

Работа с сетью идёт в отдельном потоке `updater`; с UI он общается
каналом событий: `Available(Manifest)`, `UpToDate`, `Progress(done, total)`,
`Ready(path)`, `Failed(err)`.

## 4. Поведение в приложении

Версия приложения — `env!("CARGO_PKG_VERSION")`.

**Настройки** — модуль `crates/pdfsmith-app/src/settings.rs` (крейту
обновлений они не нужны): `Settings { auto_update: bool, last_check:
Option<u64>, skipped_version: Option<String>, ask_default_app: bool }` в
`%APPDATA%\PDFsmith\settings.json`. Битый/отсутствующий файл → значения по
умолчанию (`auto_update = false`, `ask_default_app = true`). Запись
атомарная (временный файл + rename). Headless-тесты работают без файла
настроек и без сети.

**Проверка:** при запуске, если `should_check` = true, — в фоне; плюс кнопка
«Проверить сейчас» в настройках (игнорирует интервал и `skipped_version`).

**Автообновление выключено (по умолчанию):**
- Найдена версия → плашка над документом: «Доступна версия 1.2.3 ·
  Что нового · Обновить · Пропустить эту версию · ✕».
- «Обновить» → прогресс загрузки в плашке → «Перезапустить и установить».
- Перед перезапуском: если есть несохранённые изменения — диалог
  «Сохранить / Не сохранять / Отмена». Затем запуск установщика с
  `/RELAUNCH` и выход. Повторное открытие того же документа после
  перезапуска — вне рамок.
- «✕» скрывает плашку до следующего запуска.

**Автообновление включено:**
- Найдена версия → тихая загрузка в фоне; в строке состояния
  «Обновление 1.2.3 будет установлено при закрытии».
- При закрытии окна (после обычного вопроса о несохранённых изменениях)
  запуск установщика **без** `/RELAUNCH`.

**Окно «Настройки»** (кнопка-шестерёнка на панели инструментов):
переключатель «Автоматически устанавливать обновления», текущая версия,
«Проверить сейчас» с результатом («У вас последняя версия» / ошибка),
а также блок «Приложение по умолчанию» из раздела 6.

## 5. Ошибки и безопасность

- Установщик запускается только после совпадения SHA-256 с `latest.json`;
  `url` должен указывать на релизы `denfry/pdfsmith` (валидация манифеста).
  Всё только по HTTPS (rustls).
- Фоновая проверка: сетевые ошибки только в лог, пользователю ничего.
- Ручная проверка и загрузка по «Обновить»: понятное сообщение
  («Нет связи с GitHub», «Файл обновления повреждён, попробуйте ещё раз»).
- Сорвалась установка → остаётся старая версия; на следующем запуске
  обновление предложат снова (скачанный файл переиспользуется).
- Подписи кода нет: при **первой** ручной установке SmartScreen
  предупредит («Подробнее → Выполнить в любом случае»). Тихие обновления
  из приложения этого окна не вызывают.

## 6. Предложение стать приложением по умолчанию

Назначить себя обработчиком программно Windows 10/11 не даёт — только через
системный выбор пользователя. Приложение:

- **Определяет, установлено ли оно:** есть ключ
  `HKCU\Software\Classes\PDFsmith.Document` (его пишет установщик). Для
  портативного запуска без установки предложение не показывается.
- **Определяет, по умолчанию ли оно:** `ProgId` в
  `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\FileExts\.pdf\UserChoice`
  (и в `UserChoiceLatest` для новых сборок Windows 11) равен
  `PDFsmith.Document`.
- **Плашка при запуске**, если установлено, не по умолчанию и
  `ask_default_app = true`: «Сделать PDFsmith программой для PDF по
  умолчанию? · Сделать · Не спрашивать». Плашка обновлений, если есть,
  показывается первой; обе одновременно не показываются.
- **«Сделать»** открывает системный диалог выбора для `.pdf`
  (`SHOpenWithDialog`, те же флаги, что в установщике) в отдельном потоке,
  чтобы окно не замирало; при ошибке — `ms-settings:defaultapps`. После
  закрытия диалога состояние проверяется заново; стало по умолчанию —
  плашка исчезает.
- **«Не спрашивать»** → `ask_default_app = false`.
- **В настройках:** «PDFsmith — программа по умолчанию для PDF ✓» либо
  кнопка «Сделать по умолчанию» (работает всегда, независимо от
  `ask_default_app`).

Типы файлов — только `.pdf`: другие форматы приложение не открывает
(изображения попадают в него через конвертер).

## 7. Тестирование

- Юнит-тесты `pdfsmith-update`: `is_newer` (включая пре-релизы),
  `should_check` на границе 12 ч, `skipped_version`, разбор и валидация
  манифеста (чужой домен, битый hash, битая версия), проверка хэша на
  временном файле, чтение битого `settings.json`.
- Скачивание тестируется на локальном HTTP-сервере в тесте
  (`std::net::TcpListener` в потоке) — без выхода в интернет; для этого
  базовый URL и префикс валидации передаются параметрами.
- Headless-тест UI (`updates::tests`): событие `Available` показывает плашку,
  «Пропустить» пишет `skipped_version`; автообновление шлёт `Download`;
  `exit_action` отдаёт путь и флаг перезапуска.
- Юнит-тесты `settings`: битый файл, частичный JSON, атомарная запись.
- Решение «показывать ли плашку по умолчанию» — чистая функция, тестируется
  без реестра; чтение реестра проверяется вручную.
- Ручная сквозная проверка: выпустить `v0.1.1`, поставить её,
  выпустить `v0.1.2` → плашка появилась, обновление встало, программа
  перезапустилась с новой версией; повтор с включённым автообновлением.
  Проверить, что тихое обновление не открывает диалог «по умолчанию».

## Вне рамок (YAGNI)

- Подпись кода, откат на предыдущую версию, каналы beta/stable.
- Централизованное развёртывание (MSI, GPO), per-machine установка.
- Дельта-обновления, восстановление открытого документа после перезапуска.
- Поддержка прокси.

## Критерии готовности

1. `git push` тега `vX.Y.Z` без ручных шагов даёт Release с
   `pdfsmith-setup.exe`, `.sha256` и `latest.json`.
2. `pdfsmith-setup.exe` ставится без прав администратора поверх 0.1.0.
3. Установленная старая версия находит новую, показывает плашку и после
   «Обновить → Перезапустить» работает уже новая версия.
4. С включённым автообновлением новая версия ставится при закрытии,
   без вопросов.
5. Подменённый установщик (хэш не совпал) не запускается.
6. Тихое обновление не показывает никаких окон установщика.
7. Установленное приложение, не назначенное по умолчанию, предлагает
   это при запуске; после выбора в системном диалоге плашка исчезает;
   «Не спрашивать» больше её не показывает.
