# PDFsmith — Подпроект №1: текстовый слой (поиск + выделение/копирование)

Дата: 2026-06-22
Статус: на ревью
Часть мастер-карты: `docs/superpowers/2026-06-22-master-roadmap.md`

## Цель

Добавить текстовый слой: поиск по документу (Ctrl+F) с подсветкой и переходом к
совпадениям и выделение текста мышью с копированием в буфер. Это превращает
«просмотрщик растровой картинки страницы» в полноценный PDF-просмотрщик и
закладывает текстовый фундамент, переиспользуемый поиском-в-прокрутке (№2) и
OCR (№6).

## Контекст (текущая архитектура)

- `crates/pdfsmith-pdfium/src/lib.rs` — тонкая обёртка над `FPDF_*`: `Document`,
  `Page` (дорогая `load_page`, держится загруженной), `render_region` с
  матрицами поворота. Биндинги `pdfium-render 0.9.1` уже экспортируют
  `FPDFText_*`/`FPDFLink_*`/`FPDFBookmark_*` (проверено).
- `crates/pdfsmith-app/src/render_thread.rs` — единственный поток с pdfium
  (библиотека не потокобезопасна). `Job`/`Event` через каналы; страница
  держится загруженной (`loaded`); устаревшие задачи отменяются проверкой
  `job_rx.try_recv()` между тайлами.
- `crates/pdfsmith-app/src/main.rs` — egui-приложение. `View { offset, zoom }`,
  `page`, `rotation`, `page_pt()` (отдаёт размер повёрнутой страницы), маппинг
  screen = `offset + pt * zoom`, отрисовка прямоугольников painter'ом (см.
  `stroke_rect`, рамка миникарты).

## Объём

### Входит
- Извлечение текста страницы через `FPDFText_*`.
- Поиск по документу: панель Ctrl+F, регистронезависимо по умолчанию, тумблеры
  «учитывать регистр» и «целое слово»; навигация next/prev (Enter / Shift+Enter,
  дублируется кнопками ↑/↓); счётчик «N из M»; подсветка всех совпадений на
  видимой странице, активное — ярче; переход к активному совпадению.
- Выделение текста мышью: drag выделяет диапазон символов; подсветка выделения;
  копирование (Ctrl+C и пункт контекстного меню «Копировать»). Двойной клик —
  слово (по разбиению pdfium); тройной — строка. I-beam-курсор над текстом.

### Не входит (по мастер-карте)
- Прокрутка к совпадению через несколько страниц без перелистывания — №2
  (сейчас «переход» = переключить страницу и отцентрировать).
- Сайдбар/оглавление и подсветка результатов в нём — №3.
- OCR сканов — №6. На странице без текстового слоя поиск ничего не находит:
  показываем явное «На этой странице нет текста (возможно, скан — распознавание
  появится позже)».
- Поиск по нескольким документам/вкладкам (вкладок нет).

## Архитектура

### Слой 1 — биндинг текста (`pdfsmith-pdfium`, новый модуль `text`)

Типы (координаты — в **PDF-пространстве страницы**: origin внизу-слева, y вверх,
единицы — пункты):

```
struct RectPt { left, bottom, right, top: f32 }   // PDF-координаты
struct CharPt { ch: char, box_pt: RectPt }        // один символ: юникод + бокс
struct PageText { chars: Vec<CharPt> }            // индекс в Vec = индекс символа pdfium
struct MatchRange { start_char: i32, char_count: i32, rects: Vec<RectPt> }
struct FindOpts { match_case: bool, whole_word: bool }
```

По-символьная модель убирает отдельный маппинг «UTF-16↔байты»: текст страницы =
`chars.iter().map(|c| c.ch).collect()`, а выделение/копирование = конкатенация
`chars[start..end]` — корректно для любого юникода (кириллица), индексы совпадают
с индексами pdfium для `find`/hit-test.

API:
- `Page::text(&self) -> Result<TextPage, PdfError>` — RAII-обёртка над
  `FPDFText_LoadPage`; `Drop` → `FPDFText_ClosePage`. Требует уже загруженной
  `Page` (как и рендер).
- `TextPage::extract(&self) -> PageText` — `FPDFText_CountChars` + на каждый
  индекс `FPDFText_GetUnicode` (символ) и `FPDFText_GetCharBox` (бокс). Индекс в
  `chars` строго совпадает с индексом символа pdfium (нужно для `find` и
  hit-test).
- `TextPage::find(&self, query: &str, opts: FindOpts) -> Vec<MatchRange>` —
  `FPDFText_FindStart/FindNext/GetSchResultIndex/GetSchCount`; прямоугольники
  матча — `FPDFText_CountRects/GetRect` (несколько rect при переносе строки).
- `TextPage::char_at(&self, x_pt, y_pt) -> Option<i32>` для hit-test выделения —
  `FPDFText_GetCharIndexAtPos` (подтверждено в биндингах).

### Слой 2 — координатный трансформ (КЛЮЧЕВОЙ РИСК)

Проблема: текст в PDF-координатах (низ-слева, y вверх, **без поворота**), а
тайлы и курсор живут в «повёрнутом page-point» пространстве (верх-слева, y вниз),
из которого screen = `offset + pt*zoom`. Нужна одна функция-источник истины:

```
fn pdf_rect_to_page_pt(r: RectPt, page_w_pt, page_h_pt, rotation) -> egui::Rect
```

Кандидат-вывод (через unrotated-TL `(xu,yu) = (xp, H - yp)`, далее поворот CW):
- rot0: `(xu, yu)`, размер `(W,H)`
- rot1: `(H - yu, xu)`, размер `(H,W)`
- rot2: `(W - xu, H - yu)`, размер `(W,H)`
- rot3: `(yu, W - xu)`, размер `(H,W)`

**Этот вывод обязателен к валидации**, т.к. у pdfium свои внутренние соглашения
о направлении осей в матрице `render_region`. Способ валидации — не только
алгебра, но и **golden-тест выравнивания**: на тестовом PDF берём бокс
известного символа, переводим в screen-пространство и проверяем, что он
попадает на отрисованный глиф соответствующего тайла (сверка по нескольким
точкам при rotation 0/1/2/3). Источник истины — этот тест; формула правится
под него. Модуль — `pdfsmith-engine` (рядом с `viewport`), чтобы быть
тестируемым без UI и pdfium.

### Слой 3 — поток рендера (`render_thread.rs`)

Новые `Job`:
- `Job::Search { query: String, opts: FindOpts, start_page: usize }` —
  **инкрементальный** поиск: сперва `start_page` (мгновенный отклик), затем
  остальные страницы по кругу в фоне; матчи стримятся по мере нахождения;
  отменяется приходом нового `Job` (паттерн `try_recv`, уже есть для тайлов).
- `Job::PageText { page }` — ленивое извлечение текста страницы для выделения
  (по началу взаимодействия с текстом).

Новые `Event`:
- `Event::SearchPage { page, matches: Vec<MatchPt> }` где
  `MatchPt { rects_page_pt: Vec<Rect>, start_char, char_count }` — прямоугольники
  уже переведены в page-point пространство (с учётом текущего `rotation`).
- `Event::SearchProgress { scanned: usize, total: usize }`.
- `Event::SearchDone { total_matches: usize }`.
- `Event::PageText { page, chars: Vec<(char, Rect)> }` — символ + его бокс уже в
  page-point пространстве (с учётом текущего `rotation`). Текст выделения =
  конкатенация символов диапазона; копия не требует обратных преобразований.

**Кэш текста.** Извлечённый `PageText` кэшируется в памяти (per page) внутри
`Worker`; повторный поиск/копирование не платят за повторное извлечение.
Опционально — дисковый кэш текста (как тайлы) для мгновенного повторного поиска
на тяжёлых чертежах. Базовая версия — память; диск как улучшение, если успеем
(не блокирует критерии готовности).

**Производительность.** `FPDFText_LoadPage` требует `FPDF_LoadPage` (для плотных
чертежей ~2.7 с/страница). Поэтому поиск инкрементальный, с прогрессом и
отменой, текущая страница первой. На практике документы — много дешёвых
страниц, чертежи — мало страниц; кэш делает повтор бесплатным.

### Слой 4 — UI (`main.rs`)

- **Панель поиска:** Ctrl+F открывает/фокусирует, Esc закрывает. Поле ввода,
  счётчик «N/M», кнопки ↑/↓, тумблеры «Aa» (регистр) и «|w|» (целое слово),
  спиннер фонового сканирования. Enter — следующее, Shift+Enter — предыдущее.
- **Подсветка совпадений:** полупрозрачная заливка прямоугольников painter'ом
  поверх страницы (как рамка миникарты — без изменений GPU-пайплайна). Активное
  совпадение ярче; при смене активного — переключение на его страницу и
  центрирование (переиспользуем существующую логику `set_page` + центрирование
  на rect).
- **Выделение:** hit-test символа (`char_at`/кэш `chars`); диапазон от якоря
  (press) до текущего (drag); заливка по боксам символов диапазона; `Ctrl+C` и
  контекстное меню → `ctx.copy_text(selected)` (буфер обмена egui, **без новых
  зависимостей**). I-beam-курсор над текстовой областью.
- Состояние в `ViewerApp`: активный запрос, найденные матчи (по страницам),
  индекс активного, выделение (страница + диапазон символов + кэш `chars`).

## Поток данных (поиск)

1. Пользователь вводит запрос → UI шлёт `Job::Search { start_page = self.page }`.
2. Поток: для каждой страницы (текущая первой) — берёт/строит `PageText` (кэш),
   `find()`, переводит rects в page-point, шлёт `Event::SearchPage` + прогресс;
   между страницами проверяет отмену.
3. UI копит матчи, обновляет «N/M», рисует подсветку; ↑/↓ двигают активный
   индекс (переключая страницу и центрируя при необходимости).

## Обработка ошибок и краёв
- Страница без текста → пустой `PageText`; поиск по документу из одних таких
  страниц → «ничего не найдено / нет текста (возможно, скан)».
- Пустой запрос → подсветка снята, счётчик скрыт.
- Документ закрыт/сменён во время поиска → текущий поиск отменяется (новый Job /
  закрытие канала), без паник.
- Не-ASCII (кириллица): корректные индексы UTF-16↔байты для выделения/копии.

## Тестирование
- **Юнит (`pdfsmith-engine`):** `pdf_rect_to_page_pt` для rotation 0/1/2/3 на
  синтетических размерах — точные ожидаемые координаты; парсинг диапазонов матчей.
- **Golden-выравнивание:** на реальном текстовом PDF бокс известного символа
  после трансформа попадает на глиф (сверка точек, все повороты).
- **Интеграция (рядом с `render_real_pdf.rs`):** `extract` непуст на текстовом
  PDF; `find` находит ожидаемое число совпадений с непустыми rects; на странице
  без текста — пусто и без паники; кириллический запрос находится и копируется
  байт-в-байт.
- **Ручной чек-лист:** Ctrl+F, next/prev, счётчик, точность подсветки при зуме и
  всех поворотах, выделение+копирование, поведение на скане, отмена/прогресс.

## Критерии готовности
1. Ctrl+F находит текст, показывает «N/M»; ↑/↓ (и Enter/Shift+Enter) листают
   совпадения; активное центрируется на своей странице.
2. Подсветка совпадений и выделения точно ложится на текст при любом зуме и всех
   4 поворотах (подтверждено golden-тестом).
3. Выделение мышью + Ctrl+C копирует корректный текст, включая кириллицу.
4. На странице-скане (без текста) — внятное сообщение, без зависаний и паник.
5. UI не блокируется при поиске по многим страницам: виден прогресс, поиск
   отменяется при новом запросе/закрытии.

## Вне рамок (YAGNI для №1)
- Регулярные выражения и поиск с подстановками.
- Постоянная подсветка/закладки результатов между сессиями.
- Экспорт выделенного в форматах, кроме простого текста.
- Дисковый кэш текста обязателен (он — опциональное улучшение).
