# Производительность рендеринга: замеры и выводы

Измерено на реальном тяжёлом чертеже `test_pdfs/2026  ЛИВНЕВка 28.02..pdf`
(1 страница, 1684×2384 pt), release-сборка, PDFium 7763, низкоуровневый слой
биндингов (`FPDF_*`).

## Сырые замеры (низкоуровневый слой)

| Операция | Время |
|---|---|
| Открытие документа + размеры всех страниц (`FPDF_GetPageSizeByIndexF`) | **~4 мс** |
| Загрузка страницы (`FPDF_LoadPage`, разбор content stream) | **~2.7 с** |
| Полный рендер уже загруженной страницы (scale 1.0) | ~2.4 с |
| **Тайл 512×512 при зуме 4× (clipped)** | **~48 мс** |

> Прежние ~3.1 с «на открытие» были артефактом high-level API pdfium-render,
> который грузил все страницы ради их размеров. Сырой `FPDF_GetPageSizeByIndexF`
> даёт размеры за миллисекунды — виртуализация страниц фактически бесплатна.

## Выводы

1. **Открытие почти бесплатно.** Размеры страниц берутся без загрузки контента →
   многостраничники и виртуализация открываются мгновенно.

2. **Единственная тяжёлая разовая цена — загрузка страницы (~2.7 с):** PDFium
   разбирает плотный векторный content stream. Платится один раз; страницу
   держим загруженной и рендерим из неё много тайлов.

3. **Стоимость рендера ∝ числу объектов в области.** Полный рендер ~2.4 с, но
   **клиппинг-тайл считает только свою долю объектов** → тайл 512×512 даже при
   зуме 4× рендерится ~48 мс. Это и есть ключ к интерактивности.

4. **Сглаживание не влияет** на стоимость — узкое место в обходе объектов.

## Стратегия (подтверждённая замерами)

- **Рендер тайлами, видимое — первым.** Вместо одного полного рендера (2.4 с)
  режем на тайлы (~50 мс каждый) и рисуем сначала те, что в центре экрана.
  Первая осмысленная картинка — за доли секунды после загрузки страницы.

- **Загрузка страницы (~2.7 с) — с индикатором прогресса,** один раз при первом
  обращении к странице. Откладывается, пока тайлы берутся из дискового кэша.

- **Панорама/зум — GPU.** Готовые тайлы двигаются/масштабируются на видеокарте.
  Новые видимые тайлы досчитываются в фоне (~50 мс); пока не готовы — показываем
  апскейл ближайшего LOD (размыто→резко). UI никогда не блокируется.

- **LRU-кэш тайлов с бюджетом памяти** (защита слабых ПК) + **дисковый кэш**
  (чертёж не меняется → повторное открытие мгновенно, загрузку страницы можно
  отложить до промаха кэша).

## Honest-обещание «без лагов»

UI никогда не зависает. После первого открытия файла: ~2.7 с загрузка страницы
(прогресс, один раз; при дисковом кэше — только при самом первом открытии), далее
тайлы появляются за доли секунды, панорама/зум — плавные на GPU, резкость догоняет
асинхронно.
